Tools Reference

Complete documentation for all Code Council tools

review_code

General-purpose code review for any language

Parameters

ParameterTypeDescription
code*stringThe code to review
languagestringProgramming language (typescript, python, etc.)
contextstringAdditional context about the code
output_formatstringmarkdown (default), json, or html

Example

Use review_code to check this TypeScript function:

function processUser(data: any) {
  const query = `SELECT * FROM users WHERE id = ${data.id}`;
  return db.execute(query);
}

What It Checks

Security vulnerabilities, bugs, performance issues, code quality, best practices, error handling, and more.

review_frontend

Specialized review for UI/UX code

Parameters

ParameterTypeDescription
code*stringThe frontend code to review
frameworkstringFramework (react, vue, svelte, angular)
review_typestringaccessibility, performance, ux, or full (default)
contextstringAdditional context
output_formatstringmarkdown (default), json, or html

Review Types

accessibility - WCAG compliance, screen readers, keyboard nav performance - Re-renders, bundle size, lazy loading ux - User experience patterns, interactions full - All of the above

Example

Use review_frontend with review_type=accessibility to check this React component:

function Button({ onClick, label }) {
  return <div onClick={onClick}>{label}</div>;
}

review_backend

Security-focused review for APIs and servers

Parameters

ParameterTypeDescription
code*stringThe backend code to review
languagestringLanguage/framework (node, python, go, rust)
review_typestringsecurity, performance, architecture, or full (default)
contextstringAdditional context
output_formatstringmarkdown (default), json, or html

Review Types

security - SQL injection, XSS, auth issues performance - Query optimization, caching architecture - Design patterns, scalability full - All of the above

Example

Use review_backend with review_type=security to analyze this API endpoint:

app.post('/api/users', (req, res) => {
  const { email, password } = req.body;
  db.query(`INSERT INTO users VALUES ('${email}', '${password}')`);
});

review_plan

Review implementation plans before coding

Parameters

ParameterTypeDescription
plan*stringThe implementation plan to review
review_typestringfeasibility, completeness, risks, timeline, or full (default)
contextstringProject constraints or context
output_formatstringmarkdown (default), json, or html

Review Types

feasibility - Technical viability completeness - Missing steps, edge cases risks - Security, scalability issues timeline - Effort estimation

Example

Use review_plan to analyze this implementation plan:

## User Authentication Feature
1. Add login/logout endpoints
2. Store passwords in database
3. Use cookies for sessions
4. Deploy to production

review_git_changes

Review changes directly from git

Parameters

ParameterTypeDescription
review_typestringstaged (default), unstaged, diff, or commit
commit_hashstringRequired when review_type is "commit"
contextstringAdditional context about the changes
output_formatstringmarkdown (default), json, or html

Review Types

staged - git diff --cached unstaged - git diff diff - git diff main..HEAD commit - specific commit (requires commit_hash)

Examples

Use review_git_changes to review my staged changes
Use review_git_changes with review_type=commit and commit_hash=abc123
Use review_git_changes with review_type=diff to review all changes on this branch

discuss_with_council

Multi-turn conversations with the AI council

Parameters

ParameterTypeDescription
message*stringYour message or question
session_idstringSession ID to continue existing discussion
discussion_typestringcode_review, plan_review, or general (default)
contextstringAdditional context (code, plans, etc.)

Features

Per-model context: Each model maintains its own conversation history for authentic diverse perspectives.

Session persistence: Sessions last 30 minutes of inactivity.

Rate limiting: 10 requests per minute per session.

Examples

Use discuss_with_council to ask: What's the best way to implement error handling here?
Use discuss_with_council with session_id=abc123 to ask: Can you elaborate on that?

tps_audit

Toyota Production System analysis for codebases

Parameters

ParameterTypeDescription
pathstringPath to repository (auto-detects git root)
focus_areasstring[]Areas to focus on (flow, waste, security, etc.)
max_filesnumberMax files to analyze (default: 50, max: 100)
file_typesstring[]File extensions to include
include_sensitivebooleanInclude sensitive files (default: false)
output_formatstringhtml (default), markdown, or json

What It Analyzes

Flow - Data/control flow, entry points Muda - 7 wastes (defects, waiting, etc.) Bottlenecks - Constrained areas Jidoka - Built-in quality, error handling

Security

Automatically skips sensitive files (.env, credentials, keys). Scans for embedded secrets. Validates paths to prevent traversal attacks.

Output

Reports saved to .code-council/: tps-audit.html, tps-audit.md, tps-audit.json

Example

Use tps_audit to analyze this repository with focus_areas=["security", "performance"]
